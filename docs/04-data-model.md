# Data model

Authoritative entities live in the simulation. Names below are conceptual; C# naming should follow project conventions (`PascalCase` types).

## Identity

- Use strongly typed ID wrappers or readonly record structs: `CityId`, `VehicleId`, `RouteId`, `CompanyId`.
- Map pack content IDs are stable strings or ints assigned at authoring time (e.g. `city.warsaw`).
- Runtime instance IDs (vehicles, routes) are generated by the simulation.

## Entity overview

```text
MapPack
  └── City[]
  └── RailEdge[]          (MVP)
  └── Airport flags       (on City)

GameState
  ├── Clock
  ├── Company
  │     ├── Money Cash
  │     ├── Vehicle[]
  │     └── Route[]
  ├── DemandModel         (computed or cached OD matrix)
  └── RngSeed
```

## Money

- Prefer integer **minor units** (cents) to avoid float money bugs.
- Display layer formats to major units.

## Clock

| Field | Notes |
|-------|--------|
| TickIndex | long |
| SimTime | TimeSpan or hours since start |
| HoursPerTick | config |

## Demand cache

Either:

- Recompute OD matrix when populations change (rare), or
- Store `DemandEdge { From, To, PassengersPerDay }`.

Simulation samples demand per tick as `PassengersPerDay * (TickDuration / Day)`.

## Commands (payload sketches)

| Command | Key fields |
|---------|------------|
| `NewGameCommand` | MapPackId, CompanyName, Seed |
| `BuyVehicleCommand` | TypeId |
| `CreateRouteCommand` | Name, Mode, Stops[], PricePerKm |
| `UpdateRouteCommand` | RouteId, optional Name/Stops/Price |
| `AssignVehicleCommand` | VehicleId, RouteId |
| `UnassignVehicleCommand` | VehicleId |
| `SetPausedCommand` / speed | often interface-only pacing; if recorded, include |
| `SellVehicleCommand` | Later |

Each command returns `CommandResult { Success, ErrorCode, ErrorMessage }`.

## Save game

Serialize `GameState` + content pack id + schema version.

```text
SaveGame
  SchemaVersion
  MapPackId
  RngState
  Clock
  Company
  (derived demand can be recomputed)
```

Do not serialize Godot node paths or UI selection.
